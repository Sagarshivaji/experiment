Leo Design System — Color Foundation

A structured 3-tier token architecture (Primitive, Semantic, Component) connecting Figma variables to production CSS for scalable multi-brand enterprise software.

Phase 1: Architecture Challenge

Why Primitive Hex Values Fail Enterprise Scale

Hardcoded hex values create visual drift, break dark mode parity, and turn simple brand theme updates into weeks of refactoring. When developers inspect Figma files and see arbitrary values like #1E40AF, they are left guessing intent: Is this a background? A border? An interactive hover state?

The Leo Design System solves this through a rigorous 3-tier abstraction model:

[ Tier 1: Primitive Tokens ] └── color-blue-500 = #3b82f6 (raw palette values) [ Tier 2: Semantic Tokens ] └── color-action-primary = {color-blue-500} (meaningful aliases) [ Tier 3: Component Tokens ] └── btn-primary-bg = {color-action-primary} (component scopes)
Phase 2: Primitive Palette

Global Primitive Ramp

The foundation defines a 10-step luminance ramp for neutral grays, brand blues, emerald success, and rose error tones calibrated for perceptual lightness balance.

Phase 3: Semantic Layer

Light & Dark Mode Parity

Semantic tokens assign purposeful roles (Surface, Text, Border, Action). By swapping semantic mappings between light and dark modes, applications achieve automated theme switching without touching component CSS.

Phase 4: Component States

Interactive State Tokens

Every interactive element features documented token bindings for default, hover, active, focused, and disabled states, verified against WCAG AA 4.5:1 contrast standards.
